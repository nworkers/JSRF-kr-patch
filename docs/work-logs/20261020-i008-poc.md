## 4. 계획과 달라진 것

* **reJSRF 확인 경로**: PLAN §5 P4 완료 기준은 "US XBE + Language=Japanese"였지만, 설계 §4대로 일본판 빌드(reJSRF #108)로 확인했다. 그래야 XBE 메뉴 문자열까지 같은 XBE로 볼 수 있다. US XBE 경로(`out/poc/rejsrf/default.xbe`)는 만들었지만 실행하지 않았다(**미확정**, P8에서 필요하면 확인).
* **xemu의 미션 목표·메뉴**: xemu에서는 로보이 대사만 봤다. 같은 출력이 Cxbx-Reloaded에서 세 줄 모두 나왔고 xemu에서도 대사가 같게 나왔으므로 P4 확인으로 충분하다고 봤다.
* **XBE 문자열 4개**(§1 표 마지막 줄): 어느 화면에 나오는지 찾지 못했다. 메뉴 표 위치로 보면 리트라이 메뉴·B 버튼 안내·트라이얼 목표 쪽이다(**추정**). P5에서 문장 전체를 다룰 때 확인한다.
* **환경**: 10/21부터 다른 컴퓨터에서 했다(§7). 출력을 다시 만들어 MD5가 같은지 확인한 뒤 이어 갔다.

## 5. 결정

* **한글 간격**: 잉크 폭 약 18픽셀, 2바이트 간격 24픽셀이라 글자 사이가 조금 넓다. P4에서는 고치지 않고 P5 이후로 미룬다(사용자에게 제안했고 반대가 없었다). 고치는 방법(글리프 크기 `BOX_*`, 간격)은 그때 설계한다.
* **reJSRF 범위**: 일본판 빌드에서 대사 한 줄 확인으로 마친다.

## 6. 새로 안 사실

자세한 내용은 [analysis/text-files.md](../analysis/text-files.md)에 옮겼다. 요점:

* 미션 파일은 `NORM` 머리가 없고 목표가 "일본어 NUL 영어 NUL" 짝이다. NUL로 채운 짧은 문장도 문제없다.
* 대화 이벤트는 한 문자열 안에 머리·메시지·영어가 이어지고 `0x01` 바이트가 있다.
* XBE 메뉴 문자열은 `.rdata`에 있고 `.data`의 언어별 포인터 표가 가리킨다(예: 일시정지 메뉴 `0x221948`).
* 일본판은 언어 전역 `0x251F58`에 쓰지 않으므로 늘 일본어다.
* 게임은 `Media` 파일을 HDD(`Z:\Media\…`)에 캐시한다. 패치를 시험하기 전에 바꾼 파일을 캐시에서 빼야 한다. `jetfont.dat`는 캐시하지 않는다. 캐시 사본은 2048바이트 단위로 채워진다.
* 새 표에 없는 한자는 칸 위에 작은 얼룩으로 나온다. 가나는 그대로 나온다.

## 4. Deviations from the plan

* **reJSRF path**: PLAN §5's P4 criterion named "US XBE + Language=Japanese", but the check used the Japanese build (reJSRF #108) as design §4 describes, so the XBE menu strings can be seen with the same XBE. The US XBE path (`out/poc/rejsrf/default.xbe`) was built but not run (**unresolved**; checked in P8 if needed).
* **Mission objective and menu in xemu**: only Roboy's line was looked at in xemu. The same output showed all three lines in Cxbx-Reloaded and the line looked the same in xemu, which was judged enough for P4.
* **Four XBE strings** (last row of §1): the screens that show them were not found. By the menu tables' positions they belong to the retry menu, the B-button hint and the trial objectives (**inferred**); checked in P5 when all text is handled.
* **Environment**: from 10/21 the work moved to another computer (§7); the output was rebuilt and its MD5s checked before carrying on.

## 5. Decisions

* **Hangul spacing**: ink about 18 px wide against a 24 px double-byte advance spreads the letters slightly. Not changed in P4; deferred to P5 or later (proposed to the user with no objection). How to change it (glyph size `BOX_*`, the advance) is designed then.
* **reJSRF scope**: ends with one talk line confirmed in the Japanese build.

## 6. New findings

Moved in detail into [analysis/text-files.md](../analysis/text-files.md). In short:

* Mission files have no `NORM` header; objectives are "Japanese NUL English NUL" pairs; a shorter string filled with NULs works.
* A talk event holds the head, messages and English in one string, with a `0x01` byte inside.
* XBE menu strings are in `.rdata`, pointed to by per-language pointer tables in `.data` (for example the pause menu at `0x221948`).
* The Japanese build never writes the language global `0x251F58`, so it is always Japanese.
* The game caches `Media` files on the HDD (`Z:\Media\…`); changed files must be taken out of the cache before testing. `jetfont.dat` is not cached. Cached copies are padded to 2048-byte units.
* Kanji missing from the new table show as small smudges over the cell; kana show as before.
