# 작업 로그: 한국어 글꼴 — 글리프 표 데이터 패치(A′)와 아틀라스 생성 (issue #6, P3)

설계: [design/20261020-i006-korean-font.md](../design/20261020-i006-korean-font.md) · 작업 지시: [20261020-i006](../work-orders/20261020-i006-korean-font.md)

## 한 일

1. issue #6을 만들고 브랜치 `i006-korean-font`를 main(`b2accb3`)에서 만들었다.
2. 설계를 쓰고 사용자 승인을 받았다. 글꼴은 사용자가 Do Hyeon을 골랐다.
3. Do Hyeon Regular(`DoHyeon-Regular.ttf`, MD5 `7a1fcce495fba0b2009d3a484222abd1`), `OFL.txt`, `METADATA.pb`를 google/fonts `ofl/dohyeon`(커밋 `47d54ca`)에서 받아 `patch/font/`에 두었다. 정적 `glyf` TTF이고 KS X 1001 2,350자가 모두 있다. `THIRD_PARTY_NOTICES.md`에 적었다.
4. 원래 한자 1,117칸의 잉크 범위를 쟀다: 가로 2~23, 세로 3~22가 가장 많다. 원래 alpha는 4비트 중 0, 1, 3, 5, 6, 8, 9, 11, 13, 15 단계를 쓴다. 한글은 2,350자 공통 배율로 이 상자에 맞췄다(배율 0.02509 px/unit, 한글 폭 약 18픽셀).
5. `tools/font/`에 래스터라이저(`ttf.py`), 고정 대응(`hangul.py`), DXT3(`dxt3.py`), 표 배치(`glyph_table.py`), 명령줄(`build_font.py`)을 만들었다. 모두 표준 라이브러리만 쓴다.
6. XBE 섹션 요약값이 `SHA-1(u32 raw 크기 + raw 데이터)`임을 일본판 11개 섹션에서 확인하고, 패치한 `.data`의 요약값을 다시 계산하게 했다.
7. **설계를 고쳤다**: 즉치 `0x3C7AC`로 표를 1,444칸까지 늘리는 선택지는 불가능하다. 표가 바로 뒤의 1바이트 표 `0x1F8640`을 덮는다. 설계 §2와 분석 문서 §4.1·§9(P2에서 쓴 "즉치 하나로 1,444칸")를 고쳤다. 한글은 가나를 남기면 1,158자, 빼면 1,327자까지다.
8. 인계 문서에 P3 절을 더했다.

# Work log: Korean font — glyph-table data patch (A′) and atlas building (issue #6, P3)

Design: [design/20261020-i006-korean-font.md](../design/20261020-i006-korean-font.md) · Work order: [20261020-i006](../work-orders/20261020-i006-korean-font.md)

## Done

1. Created issue #6 and branch `i006-korean-font` from main (`b2accb3`).
2. Wrote the design and got the user's approval; the user chose Do Hyeon as the font.
3. Fetched Do Hyeon Regular (`DoHyeon-Regular.ttf`, MD5 `7a1fcce495fba0b2009d3a484222abd1`), `OFL.txt` and `METADATA.pb` from google/fonts `ofl/dohyeon` (commit `47d54ca`) into `patch/font/`. It is a static `glyf` TTF with all 2,350 KS X 1001 syllables. Listed in `THIRD_PARTY_NOTICES.md`.
4. Measured the ink box of the 1,117 original kanji cells: mostly x 2–23, y 3–22. The original alpha uses levels 0, 1, 3, 5, 6, 8, 9, 11, 13 and 15 of 4 bits. Hangul is fitted to this box with one scale for all 2,350 syllables (0.02509 px/unit, Hangul about 18 px wide).
5. Added the rasterizer (`ttf.py`), the fixed map (`hangul.py`), DXT3 (`dxt3.py`), the table layout (`glyph_table.py`) and the command line (`build_font.py`) under `tools/font/`, all standard library only.
6. Confirmed on the 11 sections of the Japanese build that the XBE section digest is `SHA-1(u32 raw size + raw data)`, and made the tool recompute the patched `.data` digest.
7. **Corrected the design**: growing the table to 1,444 entries via the immediate at `0x3C7AC` is impossible, because the table would overwrite the single-byte table `0x1F8640` right after it. Fixed design §2 and analysis §4.1 and §9 (P2's "1,444 with one immediate"). Hangul reaches 1,158 syllables with kana kept, 1,327 without.
8. Added a P3 section to the handoff.
