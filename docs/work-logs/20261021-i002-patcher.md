## 4. 계획과 달라진 것

* **`xbepatch.py`**: 설계 표에 없던 모듈을 더했다(큰 파일에 몰지 않는 규칙). 설계 §2.1에 반영.
* **`norm:` 자리와 NUL**: 이벤트 문장은 항목 데이터 끝까지 가고 NUL 종료는 항목 길이에 들어가지 않는다(117개 모두, 그중 5개는 패딩도 없음). 처음 구현은 문장 뒤 NUL을 요구해 실제 문장을 받지 못했으므로, `norm:` 자리에서는 항목 끝을 끝으로 인정하게 고쳤다. 설계 §3.1과 [containers §3](../analysis/containers.md)에 반영.
* **이벤트 문장의 자리**: 조사 초기에 "`$e`가 들어간 항목"을 세어 자식 3번 등도 후보로 보았으나, 효과·적·플레이어 파일 등의 2진 자료가 우연히 같은 바이트를 가진 것이었다. 실제 이벤트 문장은 `e###.dat`의 `2/0` 한 자리(117개 파일)뿐이다. 분석 문서는 고친 결론만 적었다.
* **기본 출력의 한자**: 문장이 없으면 새 표에 한자가 없어 일본어 한자가 얼룩으로 나온다. 설계대로이며, 번역 전까지 기본 출력은 시험용이라고 가이드에 적었다.

## 5. 새로 안 사실

자세한 내용은 [analysis/containers.md](../analysis/containers.md).

* `MULT`/`NORM`: 머리 + 연결 사슬, 상대값, `NORM` 패딩 0·16바이트 경계, 길이 0 항목의 `flag` 1. 패딩과 `flag`는 계산할 수 있어 원본 바이트를 보관할 필요가 없다.
* 이벤트 문장은 `e###.dat` 항목 `2/0`에, 앞쪽 `u32` 값들 뒤에 한 줄로 있다. `e###.bin`에는 문장이 없다.

## 4. Deviations from the plan

* **`xbepatch.py`**: a module not in the design table was added (the rule against monolithic files); reflected in design §2.1.
* **`norm:` places and NUL**: event text runs to the end of the item's data and the NUL terminator is not counted in the item length (all 117; 5 of them have no padding either). The first implementation required a NUL after the string and refused real text, so a `norm:` place now accepts the item's end as the end; reflected in design §3.1 and [containers §3](../analysis/containers.md).
* **Where event text sits**: early in the survey, counting "items containing `$e`" also suggested child 3 and others, but those were binary data in effect, enemy and player files that happen to contain the bytes. Real event text is only at `2/0` of `e###.dat` (117 files); the analysis records only the corrected conclusion.
* **Kanji in the default output**: with no text, the new table has no kanji, so Japanese kanji show as smudges. That is by design; the guide says the default output is for testing until the translation exists.

## 5. New findings

Details in [analysis/containers.md](../analysis/containers.md).

* `MULT`/`NORM`: a header plus a chain of links, relative values, zero `NORM` padding to 16-byte boundaries, `flag` 1 for length-0 items. Padding and `flag` can be computed, so no original bytes need keeping.
* Event text sits in item `2/0` of `e###.dat`, one line after leading `u32` values; `e###.bin` holds no text.
