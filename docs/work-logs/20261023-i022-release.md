## 1. 결과

* 릴리스 산출물 세 가지와 체크섬을 만드는 도구 `tools/release.py`와 워크플로 `ci.yml`·`release.yml`이 생겼다.

* 릴리스 노트에 해결된 issue가 없으면 릴리스가 멈춘다.

2. 실행 파일 방식 조사: PyInstaller(부트로더 GPL + 예외), cx_Freeze(폴더), 내장형 Python(폴더), Nuitka. 3. 코드: `jsrfkr.COMPILED`/`ROOT`(실행 파일에서는 모듈과 `patch/`가 같은 임시 폴더), `build_font.DEFAULT_FONT`를 `jsrfkr.ROOT` 기준으로, `patch.py`의 출력 제한(실행 파일이면 현재 폴더의 `out/`), 사용법의 명령 이름, 실행 파일에서 `--update-manifest` 막기.

6. `tests/test_release.py`(9개), `THIRD_PARTY_NOTICES.md` 실행 파일 절, `.gitignore`에 `dist/`.
7. 문서: 가이드 `apply-patch.md` §6, `tools/README.md`, PLAN P9.

## 4. 계획과 달라진 것

* 실행 파일(설계 §8)은 처음 설계(Python판만)에 없던 것으로, 사용자 요청으로 더했다.
* Linux 빌드에는 Debian Python의 `python3-venv`, `patchelf`, `python3-dev`(헤더)가 필요했다. 사용자가 WSL에 설치했다. 시험 중 `--static-libpython=no`를 넣어 보았으나 헤더가 여전히 필요해 되돌렸다. CI의 setup-python에는 헤더가 있다.
* 이미 있는 태그(v0.0.12 등)에는 `tools/release.py`가 없어 수동 실행으로도 릴리스를 만들 수 없다. 이 작업이 머지된 다음 판부터 릴리스된다.

# Work log: GitHub Actions releases and the distribution package (issue #22, P9-1)

Design: [20261023-i022](../design/20261023-i022-release.md) · Work order: [20261023-i022](../work-orders/20261023-i022-release.md) · Issue: [#22](https://github.com/nworkers/JSRF-kr-patch/issues/22)

Period: 2026-10-23. Branch `i020-readme-fix` (not `main`, so work continued on it per the rules).

## 1. Result

* `tools/release.py` and the workflows `ci.yml` and `release.yml` build three release artifacts and a checksum file:
  * `jsrf-kr-patch-v<VERSION>-windows-x64.zip`: the standalone executable `jsrf-kr-patch.exe` (Nuitka 2.8.10, patch data built in)
  * `jsrf-kr-patch-v<VERSION>-linux-x64.tar.gz`: the standalone executable `jsrf-kr-patch`
  * `jsrf-kr-patch-v<VERSION>-python.zip`: the Python-script edition
  * `SHA256SUMS.txt`
* All three make the patched `default.xbe` and ISO **from the package and the dump alone**, with the repository's results (§3).
* A release stops if its notes list no resolved issue.
* User decisions: Windows and Linux executables and the Python edition as separate artifacts; releases on tag push (and manual runs).

## 2. Done

1. Design and work order, with the user's requests (resolved issues, standalone executables, Windows and Linux).
2. Executable options surveyed: PyInstaller (GPL bootloader + exception), cx_Freeze (a folder), embeddable Python (a folder), Nuitka. After a successful trial with Nuitka 4.3.1, its installed license files showed **Nuitka is AGPL-3.0 from 4.0** (with a runtime exception); the history was checked in PyPI metadata and the build **pinned to 2.8.10, the last Apache-2.0 release** (no exception to the `AGENTS.md` licensing rule needed). Telling the user earlier that "Nuitka is Apache-2.0" was wrong for current releases; this was reported as soon as it was found.
3. Code: `jsrfkr.COMPILED`/`ROOT` (in an executable the modules and `patch/` share one temporary folder), `build_font.DEFAULT_FONT` relative to `jsrfkr.ROOT`, `patch.py`'s output rule (under `out/` in the current folder for an executable), the command name in the usage, `--update-manifest` refused in an executable.
4. `tools/release.py` (`notes`, `python`, `binary`, `sums`), `tools/release-requirements.txt` (`nuitka==2.8.10`, `zstandard==0.25.0`), `release/README.md` (the package user guide, Korean and English, with sources and rights notice).
5. `.github/workflows/ci.yml`, `release.yml` (action versions as in rePIU: `checkout@v7`, `setup-python@v7`, `upload-artifact@v7`, `download-artifact@v8`).
6. `tests/test_release.py` (9), the executable section of `THIRD_PARTY_NOTICES.md`, `dist/` in `.gitignore`.
7. Documents: guide `apply-patch.md` §6, `tools/README.md`, PLAN P9.

## 4. Deviations from the plan

* The executables (design §8) were not in the first design (Python edition only); added at the user's request.
* The Linux build needed Debian Python's `python3-venv`, `patchelf` and `python3-dev` (headers); the user installed them in WSL. Adding `--static-libpython=no` during the test still needed the headers and was reverted; CI's setup-python ships the headers.
* Existing tags (v0.0.12 and so on) lack `tools/release.py`, so even a manual run cannot release them; releases start with the version after this work is merged.
