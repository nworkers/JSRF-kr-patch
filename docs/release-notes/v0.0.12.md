## JSRF-kr-patch v0.0.12

The result of issue #20 (P6-2). **The game runs in English mode, and Korean shows where it reads its English text.** The base XBE is the dump's `default.xbe` (the US build), and the 2,276 existing translations are used as they are.

### Resolved issues

| Issue | Content | Commits |
|---|---|---|
| [#20](https://github.com/nworkers/JSRF-kr-patch/issues/20) | English-mode-based Korean patch: run as language 1 and write Korean where the English resources are read | `5ce8801`, `39d08b9`, `99a135c`, `3970fc1`, `26cdff7`, `ce168ee` |

### Changes

* **Design** ([20261023-i020-english-base.md](../design/20261023-i020-english-base.md)): the US XBE as the base (language value 1), English voices and picture assets accepted (the user's decisions); the English places are made Korean on top of the patch so far.
* **Analysis** ([english-mode.md](../analysis/english-mode.md)): the language value, English places in Media, 55 XBE language tables and 3 special places (695 language-0 slots of Japanese strings ↔ English slots).
* **Tools**: `tools/jsrfkr/english.py` (message-script language 1 = the Korean language 0, mission slot 1 → Korean, XBE English slots → Korean), `tools/analysis/en_slots.py` → `patch/xbe-en.tsv` (addresses only), `tools/check_english.py`, the English step and `--japanese-places` in `patch.py`, replacing the xiso's `default.xbe`; input checks expect the US MD5 `f4e366bf…`.
* **Documents**: `AGENTS.md` (input premise, voice scope, address rule), README, guides (`apply-patch`, `emulator-check` §6, `text-pipeline`), PLAN P6-2, the reJSRF handoff's P6-2 section.
