## JSRF-kr-patch v0.0.4

The result of issue #6 (P3). **There is now a tool that builds the Korean font.** It changes only the XBE glyph table and leaves the renderer code alone (option A′). No screen check (P4) or translation yet.

### Resolved issues

| Issue | Content | Commits |
|---|---|---|
| [#6](https://github.com/nworkers/JSRF-kr-patch/issues/6) | Korean font: glyph-table data patch (A′) and atlas building | `f91c07e`, `475464f`, `ff78d3a`, `2aa40e8` |

### Changes

* **Design** ([20261020-i006-korean-font.md](../design/20261020-i006-korean-font.md)): only the XBE `.data` glyph table `0x1F7088` and the class first indexes change. Hangul gets fixed codes from `0x8890` for the 2,350 KS X 1001 syllables: up to 1,158 with kana kept, 1,327 without.
* **Font**: Do Hyeon (SIL OFL 1.1) in `patch/font/` ([THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)).
* **Font tools** (`tools/font/`, standard library only): TrueType rasterizer, fixed Hangul codes, DXT3, table layout, `build_font.py` (writes a new `jetfont.dat` and a `default.xbe` with the new table and `.data` digest to `work/`).
* **Correction**: the table cannot grow beyond 1,390 entries (the single-byte table follows it); v0.0.3's "1,444 with one immediate" is fixed in the analysis.
* A P3 section in the reJSRF handoff.
