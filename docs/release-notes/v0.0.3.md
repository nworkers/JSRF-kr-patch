## JSRF-kr-patch v0.0.3

The result of issue #3 (P2). **The Japanese text renderer is analysed.** There is no patcher or translation yet, only analysis scripts and documents.

### Resolved issues

| Issue | Content | Commits |
|---|---|---|
| [#3](https://github.com/nworkers/JSRF-kr-patch/issues/3) | text renderer analysis: drawing functions, glyph mapping, `$` codes, size limits, `TNRoman.bin`, US correspondence | `b9e4bd7`, `e90b4a1` |

### Changes

* **Analysis** ([text-renderer.md](../analysis/text-renderer.md)): the glyph order table is in the XBE `.data` at `0x1F7088` and the table index is the cell number (4 pages × 19×19 cells, 26 px). `jetfont.dat` is six DXT3 textures. Only lead bytes `0x80`–`0x9F` start a double-byte character. There is no automatic wrapping and the page buffer is 0x100 bytes. `TNRoman.bin` is a debug font. The renderer is the same code at the same addresses in the Japanese and US builds.
* **Recommended input for P3**: patch only the XBE glyph table (A′; 1,390 cells with no code change, 1,444 with one immediate).
* **Analysis scripts** (`tools/analysis/`, standard library only): `font_tables.py`, `jetfont.py`, `renderer_compare.py`, `text_codes.py`, `xbe.py`.
* kb [shift-jis.md](../kb/shift-jis.md) and [dxt3.md](../kb/dxt3.md), the reJSRF handoff [handoff-rejsrf.md](../handoff-rejsrf.md), the changed facts in PLAN §3.
