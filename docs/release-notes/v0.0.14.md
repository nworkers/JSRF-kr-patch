## JSRF-kr-patch v0.0.14

The results of issues #26 and #25. **Cutscene subtitles now change and end with the English voice.** Since English mode (v0.0.12) the event subtitles used the Japanese version's timing, so they ended before the line or drifted from the picture. Now the English version's page count and timing are used, and the Korean subtitles are re-split automatically into the English page count. The introduction page's feature cards are in plain words too.

### Resolved issues

| Issue | Content | Commits |
|---|---|---|
| [#26](https://github.com/nworkers/JSRF-kr-patch/issues/26) | English-mode cutscene subtitle timing: use the English block's timing | `edd3322`, `03b728c`, `2714d1a` |
| [#25](https://github.com/nworkers/JSRF-kr-patch/issues/25) | Plain wording for the introduction page's feature cards | `04f9337` |

### Changes

* **Subtitle timing** ([design i026](../design/20261023-i026-subtitle-timing.md)): the English place (language 1) of each event keeps the English page count, per-page times and start delay. The 77 messages with the same page count keep the Korean pages; for the other 62, `tools/jsrfkr/resplit.py` re-splits the Korean into the English page count (preferring sentence ends, commas, connective endings and particles, aiming at the English letter shares, within the subtitle window). The translation files are unchanged; talk events are as before.
* **Check tool** `tools/check_timing.py`: computes timing values, word preservation and window limits for every event message; `--review` writes the English and Korean pages side by side to `work/`. `check_english.py` follows the new rule.
* **Analysis**: [message-script §5](../analysis/message-script.md) (timing values differ by language). **Guides**: [text-pipeline §3.2](../guides/text-pipeline.md), [translation.md](../guides/translation.md).
* **Introduction page**: the six feature cards, short and without jargon.
